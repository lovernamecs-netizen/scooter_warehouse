# 1.0 현장 테스트 버전 검증 보고서

작성일: 2026-10-05. 이 보고서는 개발 환경에서 수행한 검증 결과입니다. 실제 Windows PC와 Galaxy Fold 8에서 실행한 결과는 아닙니다.

## 검증 완료

| 구분 | 결과 | 검증 범위 |
|---|---|---|
| 서버 자동 테스트 | 14개 통과 | SQLite, Python 3.12 |
| 브라우저 업무 흐름 | 통과, JS 오류 0 | 입고 → U 설치 → 위치이동 → 주문배정 → 작업 → 출고 |
| 폴드 대응 UI | 5가지 폭 통과, JS 오류 0 | 360/412/768/884/1024 CSS px, 터치 화면 에뮬레이션 |
| 화면 전환 상태 유지 | 통과 | 접기·펼치기 크기 변경 시 입력값과 선택 차량 유지 |
| Android APK | 빌드 성공 | Gradle 8.9, AGP 8.7.3, JDK 17, SDK 35 |
| APK 구조 | 검증 성공 | apksigner v2 서명, zipalign 16KB 검사, arm64 OCR 라이브러리 LOAD 정렬 16KB |
| Windows EXE | 컴파일 성공 | .NET Windows Forms PE 실행 파일 생성 |
| 백업·복구 | 통과 | AES-GCM 백업 생성, 새 SQLite DB 복구 |

서버 테스트는 중복 VIN, 같은 Slot의 동시 배치, 실패한 이동의 원위치 유지, 오래된 버전 충돌, 점유 Grid 축소 차단, Slot ID 유지, 관리자 예외 출고 권한, 실제 수량 Snapshot, 반품, 주문 취소 후 장착품 보존, 파일 입고 검수, 일 마감 불변성, command_id 재사용 충돌을 포함합니다.

출고 중 의도적으로 DB 오류를 발생시키는 테스트에서 차량 상태·위치·주문·출고 원장이 모두 이전 상태로 롤백되는 것을 확인했습니다. 한국시간 날짜 경계, 앞자리 0이 있는 VIN, 스프레드시트 수식의 텍스트 취급, 보관처리와 재입고도 검증했습니다.

브라우저 테스트 캡처는 `docs/screenshots/`에 있습니다. 자동 테스트의 테스트 계정은 폐기 가능한 임시 DB에서만 생성되며 프로그램의 운영 기본 계정/비밀번호가 아닙니다.

## 재현 명령

프로젝트 폴더에서 개발 의존성과 Playwright Chromium을 설치한 후 실행합니다.

```sh
pip install -r requirements-dev.txt
python -m playwright install chromium
python -m pytest -q tests/test_workflow.py
python tests/ui_smoke.py
python tests/fold_smoke.py
```

테스트 환경에는 Chromium의 OS 의존 라이브러리도 필요합니다. 서버 테스트 실행 시 Starlette 테스트 클라이언트의 향후 httpx2 전환에 대한 경고 1개가 있었으며 테스트 실패는 없었습니다.

## 아직 검증하지 않은 부분

- Fold 8 실기기 설치, 실제 VIN 촬영 정확도, 카메라 권한, 키보드, 절전 후 복귀, 멀티윈도우. APK 및 웹 화면 검증만으로 실기기 호환성을 확정하지 않습니다.
- Windows 실기기 EXE 실행, Chrome 연동, 최초 Python 설치 흐름. 실행 파일 컴파일까지 완료했습니다.
- PostgreSQL 실제 동시 접속. 코드와 별도 CI 테스트 구성을 제공했지만 이번 결과는 SQLite 기반입니다.
- 외부 HTTPS 서버 배포와 실제 LTE/5G ↔ PC 통신. 서버·도메인이 아직 정해지지 않았습니다.
- 운영 백업 스케줄과 장기 부하 테스트. 백업·복구 기능 자체를 검증했습니다.

## 첫 실사용 테스트 순서

1. PC에서 테스트 차량 2대를 입고하고 VIN 검색·U 설치·위치이동을 확인합니다.
2. 점유 Slot을 포함한 Grid 축소가 막히는지 확인합니다.
3. 장착품과 전달품 수량을 다르게 지정하고 출고 후 일 마감에 각각 반영되는지 확인합니다.
4. 외부 서버를 준비한 후 PC와 폰으로 동일한 빈 Slot 이동을 동시에 시도합니다.
5. 폰에서 VIN 촬영, 수정 확인, 접기·펼치기 중 입력 유지, 통신 끊김/복귀를 확인합니다.
6. 테스트 백업을 새 DB에 복구해 차량 및 출고 대수를 비교합니다.

실제 재고 투입 전 위 확인과 PostgreSQL 테스트를 완료하십시오. 과거 출고 Snapshot은 수정하지 않으며 정정은 별도 기록으로 남깁니다.
