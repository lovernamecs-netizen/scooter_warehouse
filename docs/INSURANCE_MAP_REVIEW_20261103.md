## 원본 기능 보존

PDF 다중 선택·페이지별 JPG, 차량번호 기반 파일명과 중복 접미사, JPG 폴더/다중 파일, CSV/XLS/XLSX 연락처, 수동 번호 수정, 안내 문구 저장과 `{차량번호}` 치환, 계정 설정, 개별/선택/전체 MMS를 유지한다. 웹에서는 원본 폴더에 자동 저장하는 대신 사용자가 JPG 또는 ZIP 다운로드를 선택한다. 기존 가림 좌표 `(330,400,585,435)`와 문구 원문은 유지한다.

보험 문서가 차량 입출고나 부품 재고를 변경하지 않는다. 보험 도구는 기존 고객정보 접근 권한이 있는 관리자만 사용할 수 있다. 원격 브랜치의 worker 발송 허용은 현재 운영의 개인정보 권한 정책과 맞지 않아 적용하지 않았다.

## 차량번호 인식과 JPEG

원문의 차량번호 영역 `(10,180,500,300)`을 먼저 검사한 뒤 전체 텍스트를 확인한다. 지역식/신형식, 글자 단위 공백, 라벨의 공백, 동일 번호의 중복 검출을 처리한다. 영역 밖에 다른 번호가 있으면 후보와 확인 필요를 표시하며 추정으로 확정하지 않는다. PDF 텍스트가 없는 스캔 문서는 자동 OCR 대상이 아니므로 수동 확인·입력이 필요하다.

**MMS용 출력 상한은 199,000바이트**다. 변환·다운로드·발송 단계에서 제한을 적용하며, 서버는 파일 내용·크기·해상도를 다시 확인한다. RGB 색상·전체 비율·여백을 유지하고 Lanczos로 원본에서 리사이즈한다. 해상도를 우선 유지하면서 JPEG quality 65~95 범위에서 제한에 맞는 품질을 탐색한다. 단계별 축소도 이전 JPEG 재압축이 아닌 기준 이미지에서 수행한다. 용량을 충족하지 못하면 보류하며 JPG 저장·ZIP 포함·MMS 발송을 막는다. JPEG 손실 압축과 작은 글씨의 가독성을 무손상이라고 보장하지 않는다.

`app.txt`의 검토한 압축 함수만 추출해 같은 합성 문서를 비교했다. 두 방식 모두 비교 상한을 199,000바이트로 맞췄다.

| 합성 문서 | 원문 결과 | 개선 결과 |
|---|---|---|
| 15줄 | 847×1200 / 47,960바이트 | 1016×1440 / 127,286바이트 |
| 35줄 | 847×1200 / 95,032바이트 | 1016×1440 / 198,904바이트 |
| 60줄 | 847×1200 / 152,832바이트 | 965×1368 / 198,798바이트 |

35줄 합성 이미지의 RGB PSNR은 같은 원본 크기로 맞춰 비교했을 때 24.61→28.57dB였다. 이는 해당 합성 이미지 비교치이며 실제 보험사의 모든 문서나 사람의 가독성을 보증하지 않는다. 원본과 개선 PNG, 상세 JSON은 Git 외부 테스트 결과 폴더에 있다.

## UI와 지도

관리·도구 아래 `보험증권·MMS`를 추가했다. 기존 테이블·청록색 버튼·패널 스타일을 사용하고 이미지 준비/발송/최근 이력/접힌 오류 도움말로 나눈다. 모바일에서는 표 내부만 가로 스크롤한다.

지도 이동 모드 버튼, +/- 버튼, 휠·두 손가락 지도 확대축소를 제거했다. 기존 기본 지도 표시 비율은 유지하며, 빈 공간 한 손가락/마우스 왼쪽 드래그로 스크롤한다. 빈 자리 버튼, 차량 카드, 구역 편집 핸들은 지도 끌기의 시작 대상으로 쓰지 않는다. 차량 클릭·2초 길게 누르기·목적지 선택, 관리자의 배치 편집은 유지한다. 앱 전체 세 손가락 UI 배율 기능은 변경하지 않았다. 이전 `MAP-NAVIGATION-MODE-20261102.md`의 모드/핀치 설명은 이번 사용자 지시로 대체된다.

## 운영 전 확인 및 복구

이번 커밋은 코드 검토·격리 테스트까지이며 운영 배포/GitHub push는 하지 않는다. 이전 안정화 커밋도 아직 운영에 반영되지 않은 상태다.

1. 운영 데이터/사진/환경/암호화 키 복구 수단을 기존 절차대로 백업하고 검증한다. 기존 운영 커밋부터 이 커밋까지 차이를 확인한다.
2. 운영의 기본 Python 의존성은 무관하게 업그레이드하지 않는다. 보험 기능에는 `requirements-insurance.txt`를 추가 설치해야 한다. 개발 환경에서는 해당 버전을 설치해 검사했다.
3. CoolSMS Key/Secret은 OS keyring에, 발신번호·기본 문구는 `APPDATA/ScooterWarehouse/insurance-mms.json` 또는 `INSURANCE_CONFIG_DIR`에 있다. 기존 Tk 앱의 config.json을 자동 복사하지 않는다. 테스트에서는 별도 경로와 가짜 저장소만 사용한다. **같은 Windows 계정의 기본 keyring/config는 공유되므로 미리보기에서 실제 계정을 저장하지 않는다.** 운영 계정 설정은 배포 후 별도 수행한다.
4. 발송 이력 테이블은 DB 백업에 포함되며 합성 복구 검사를 통과했다. keyring의 API 키와 위 설정 파일은 DB/사진 ZIP에 자동 포함되지 않는다. OS 계정 변경/PC 교체 시 공급자 자격 증명 재설정과 기존 고객정보 암호화 키 복구가 필요하다.
5. DB에는 테이블/인덱스만 추가한다. 차량·입고 회차·출고 Snapshot·마감 이력 이관이나 초기화는 없다. 승인된 배포는 fast-forward로 적용하고 시작 후 읽기 검사를 한다.
6. 롤백은 되돌림 커밋으로 코드만 복구한다. 새 발송 이력이 들어간 DB를 과거 DB로 덮어쓰면 중복 발송 방지 이력이 사라질 수 있으므로 금지한다. 외부에서 이미 접수된 MMS는 코드 롤백으로 취소되지 않는다.
