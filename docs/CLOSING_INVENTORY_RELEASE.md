- 완료한 작업을 제거하거나 출처를 바꾸는 계획 변경은 차단한다. EPP/탑박스 교체 시 미완료 구성품을 재계산한다.

- 코드 변경은 고유 ID를 유지하고 이전 코드를 별칭으로 보존한다. 활성/비활성 전체에 정규화 충돌 검사를 적용한다.
- 카테고리, 공급처/제품/색상/메모/호환 차종, 포장수, 표시순서, 정수 원/EA 단가와 가격 이력을 관리한다. 미입력 단가와 0원을 구분한다.
- IN/OUT/DAMAGE/RETURN/ADJUST, 여러 품목, BOX+낱개 또는 총 EA, 거래처/메모, 과거 날짜 입력을 지원한다.
- 새 거래는 당시 코드·이름·포장수·단가 Snapshot을 보존한다. 이미 저장된 과거 거래에 당시 값이 없으면 현재 값을 과거 값으로 만들어 넣지 않는다.
- 제공 수량은 날짜 없는 실사 초안이다. 날짜와 사유를 직접 입력하여 검토·확정해야 한다. '-'는 미확인이고 0으로 바뀌지 않는다.
- 수량 복사는 설정 순서와 비활성 품목 위치를 유지한다. 쉴드는 순흥/실버스타의 고정 순서로 결합한다. 전체 표에는 원/EA 단가와 파손 수량을 포함한다.
- 차량 일 마감과 재고 화면은 공통 실제 출고 집계 함수를 사용한다. B2B/B2C/기존 주문, 차종, 차량 목록, 장착/전달/조달 출처를 표시한다. VOID를 현재 실적에서 제외하며 보존 마감 Snapshot은 그대로 둔다.
- 재고 마감은 확정 당시 Snapshot과 정정 반영 현재 조회를 구분한다. 실사일 업무 종료 수량이 당일 거래와 이중 합산되지 않게 기존 경계를 유지한다.
- 외부 붙여넣기는 원문/기본/세트 추가 코드를 구분하고 코드 검색을 제공한다. 내부 출고 ID가 연결되면 자동 차감과 중복 반영을 차단한다. 연결 불명확 자료는 사용자의 명시적 외부 중복 검수 대상이다.
- 정상 수동 가져오기/새로고침 버튼을 없애고 관리 기능을 묶었다. 저장 충돌 시 입력을 유지하고 최신 재고를 재조회한다.

## 최초 관리자 설정

1. **재고 마감 → 관리 → 최신 포장수 검토**에서 기존 토시 20→12EA와 미제공 포장수의 미확인 처리를 검토한다. EA 잔량/과거 거래/확정 마감은 바꾸지 않는다. 새 DB 초기값은 이미 최신 기준이다.
2. **차종·기본품·세트 규칙**에서 실제 차종을 선택하고 PCX/NMAX/FORZA350/XMAX/ADV350/ZONTES368G/HUSKY 예시를 검토·연결한다. 이름에 PCX가 들어간다는 이유만으로 자동 연결하지 않는다. 각 모델의 '이 차종 규칙 사용'을 확인한다.
3. 기본값은 B2B SC/CUP + 차종 기본 쉴드, B2C SC다. 토시는 기본품이 아니다. 기본품 목록과 세트 구성은 관리자가 변경할 수 있다.
4. **품목·내부 코드**에서 기본 용도(장착/전달), 필요시 호환 차종/카테고리/단가를 지정한다. 용도가 미설정이면 주문에서 직접 지정해야 한다. 가격 자료는 임의로 채우지 않았다.
5. 제공 수량을 쓰려면 **실사 등록 → 제공 자료 초안 채우기** 후 실제 업무 종료 기준일과 확인 사유를 입력한다. 날짜는 자동으로 오늘을 넣지 않는다. 포장수가 미확인인 품목은 총 EA만 입력한다.
6. 소량의 실제 업무 샘플로 차종 연결·기본품 용도·공장 짐대 확인을 검토한 후 새 주문에 사용한다.

## 적용 범위와 기존 자료

- 새 주문 UI는 부품 계획을 작성한다. 구성 검토에서 품목별 용도/출처/수량을 확인한다.
- 기존 활성 주문은 차량 상세의 **부품 연동 전환**으로 명시적으로 전환한다. 미완료 기존 계획을 대체하려면 사유가 필요하다. 완료 작업을 조용히 삭제하지 않으며, 완료된 미매핑 작업은 실물과 계획을 먼저 검토해야 한다.
- 규칙을 활성화한 뒤 미연동 기존 주문은 관리자 수동 재고 검수 예외 사유가 있어야 출고할 수 있다. Snapshot에는 `LEGACY_REVIEW_REQUIRED`를 남긴다. 해당 출고는 자동 차감 대상이 아니며 연결 ID를 지정한 외부 검수로 보완한다.
- 이미 확정한 출고를 재시작/업데이트 시 소급 차감하지 않는다. 과거 누락을 반영하려면 날짜·실제 신규 사용품·연결 출고 ID를 검수한다.
- 부족/미확인 재고는 관리자 재고 예외 사유가 있어야 연동 출고 가능하다. 비활성/미등록 품목과 잘못된 차종 구성은 예외로 숨기지 않는다.
- 새로운 DB 테이블이나 파괴적 스키마 변경이 없다. 기존 PartsBook JSON에 규칙/카테고리/메타데이터를 추가하고, 기존 Setting에 주문 계획을 저장한다. 규칙을 저장할 때 버전과 감사 기록을 남긴다. 서버 시작은 사용자 설정을 초기값으로 덮어쓰지 않는다.
- VOID/CORRECTION은 원 출고 업무일에 재고 증감을 반영하여 해당일 이후 의존 마감이 재확인 상태가 된다. 기록 시각/사유와 원 출고 연결은 별도 보존한다. 다음 실사가 이전 날짜의 재고 의존성을 끊는 기존 규칙은 유지한다.
- 재고 평가금액·회계·발주 시스템은 추가하지 않았다. 가격은 정수 원/EA 입력과 거래 당시 값 보존이다.

## 업데이트 절차 — 별도 승인 후 실행

패키지 밖의 백업 폴더를 지정한다. payload에 DB/사진/.env/인증정보/키/APK/EXE가 없다.
기존 운영 폴더의 오래된 `APPLY_UPDATE.cmd`가 아니라 **이번 ZIP의 `install_patch.py`**를 사용한다.

1. 작성 중인 화면을 저장하고 모든 서버 프로세스를 종료한다. 기본 검사 포트는 8765다. 다른 포트를 사용하면 `--port`를 지정한다.
2. ZIP을 운영 폴더 밖에 푼다. SHA256SUMS와 별도 제공한 ZIP SHA-256을 확인한다.
3. 먼저 읽기 전용 사전검사를 실행한다. 아래 경로의 `패키지`와 `백업`은 실제 별도 폴더로 바꾼다.

```powershell
& 'C:\새 폴더\창고관리\scooter_warehouse\.venv\Scripts\python.exe' -X utf8 'C:\패키지\install_patch.py' --target 'C:\새 폴더\창고관리\scooter_warehouse'
```

4. 지원 기준은 main `0087e511…`의 1.0.30 소스다. 알려지지 않은 수정/추가 소스, payload 훼손, 다른 버전은 거부한다. 이미 같은 업데이트가 적용됐으면 재적용하지 않는다.
5. 별도 배포 승인을 받은 후 다음 형태로 실행한다. 실제 사용 DB 경로를 확인하며, 다른 DB를 임의로 지정하지 않는다.

```powershell
& 'C:\새 폴더\창고관리\scooter_warehouse\.venv\Scripts\python.exe' -X utf8 'C:\패키지\install_patch.py' --target 'C:\새 폴더\창고관리\scooter_warehouse' --apply --server-stopped --database 'C:\새 폴더\창고관리\scooter_warehouse\warehouse.db' --backup-root 'C:\백업\ScooterWarehouse'
```

6. 도구는 DB를 읽기 전용으로 열어 SQLite backup API로 WAL 포함 일관된 사본을 만들고 무결성을 검사한다. 변경 전 파일도 백업한다. 검증된 server/web 파일만 교체하며 DB/사진/환경/큐를 덮어쓰지 않는다.
7. 실패하면 교체한 파일만 원본 해시를 확인해 복구한다. 동시 수정이 감지되면 무조건 덮어쓰지 않고 중단한다.
8. 서버를 재시작하고 v1.0.31, 로그인, 기존 입고 회차/사진/출고/마감 열람을 확인한다. 관리자 최초 설정 후 새 주문을 사용한다. 실행 방식은 기존 Launcher/START_LOCAL_SERVER를 유지한다.

## 롤백

업데이트 이후 DB에 변경이 없을 때만 `--rollback <생성된 patch-… 백업 폴더> --server-stopped`와 동일 `--target`을 지정해 파일을 되돌릴 수 있다.
현재 파일이나 백업 해시가 다르거나 DB에 이후 기록이 생겼다면 자동 롤백을 차단한다.
DB와 사진은 롤백 명령으로 복원하지 않는다. 이후 업무 기록이 생겼다면 기존 DB를 유지한 전진 수정이 우선이며, 백업 DB를 덮어써 기록을 잃게 하지 않는다.
이 도구는 SQLite 소스 배포용이다. PostgreSQL 환경에는 검증 없이 실행하지 않는다.

## 테스트와 제한
