# 출고 준비 정렬과 고객명 표시

기준 커밋 82c049b. 운영 DB/계정/주문/출고/사진 구조는 변경하지 않는다.

- 출고 준비 목록과 해당 화면의 오늘 작업 카드: 한국시간 오늘과 출고예정일의 절대 차이가 작은 순. 동일 거리에서는 지난 날짜 우선, 동일 날짜는 주문번호 순. 날짜 없는 기록은 마지막. 다른 재고 화면의 FIFO/제조년월 정렬은 유지한다.
- PC 표에 업체·주문자 열, 모바일 카드에 이름·출고예정일 추가. 차량 상세 맨 위에 강조 영역. 기존 미등록 주문은 그대로 표시하며 자동 연결/수정하지 않는다.
- 기존 최초 admin/허용된 관리자만 이름 조회. 나머지 사용자에게는 조회 권한 없음 표시. 공용 state, 출고 Snapshot, localStorage/sessionStorage에 이름을 추가하지 않는다.
- 전용 POST /api/customers/orders는 권한 검사, 최대 200개 ID 검증, 조회 감사 기록, no-store 응답을 적용한다. 이름은 응답을 받은 현재 DOM에만 표시하며 화면 전환으로 제거된 요소를 다시 쓰지 않는다.
- 실행: test_customer_privacy.py 5개 통과(일괄조회 권한/개수제한/no-store/기존 주문 미연결 포함), customer_map_browser.py 통과(실제 격리 서버와 Chromium, 표/카드 이름, 상세 최상단, 날짜 정렬, 브라우저 영구 저장소 비포함). 최초 브라우저 테스트는 숨겨진 PC 행을 누르려다 실패했으며 터치 화면의 실제 카드 선택으로 수정해 통과. 실제 갤럭시 검증은 미실행.
- 웹/서버 패치이며 새 APK는 필요 없다. 운영 적용 전 SQLite 일관 백업을 생성하고 Git fast-forward 후 같은 데이터 경로로 재시작한다. 코드 복구는 82c049b 기준 변경의 reviewed revert로 진행하며 운영 DB를 과거 백업으로 덮어쓰지 않는다. GitHub push는 하지 않는다.

## 주문 구분 배지 추가
기준 a75345a. 먼저 확인할 출고 카드 및 출고 준비의 오늘 작업 카드·PC 표·모바일 카드에 저장된 assignment.parts_order.channel 기준 B2B(파랑)/B2C(보라) 배지를 표시한다. 값이 없는 기존 주문은 구분 미등록(회색)으로 표시하며 추정하거나 DB를 변경하지 않는다. customer_map_browser.py에서 합성 서버 응답의 B2B/B2C/기존 미등록 3가지 경우를 각 위치에서 검증했다. 실제 갤럭시 검증은 미실행. 정적 웹 파일만 변경하므로 APK/서버 재시작이 필요 없다. 복구는 이 UI 변경의 Git revert로 진행하며 DB를 복원하지 않는다.
