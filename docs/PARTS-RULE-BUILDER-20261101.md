# 기본품·세트 카드 편집기 운영 적용 — 2026-11-01

## 변경과 사용
재고 마감 → 부품 입출고·관리 → 차종·기본품·세트 규칙에서 카드 편집기를 연다.
실제 재고 마스터의 코드 카드를 끌어 놓거나, 카드 선택 후 ‘＋ 추가’한다. 한글 이름은 마우스 툴팁과 선택/구성 목록에 표시한다.
공통 B2B/B2C 기본품, 차종별 별도 기본품, 박스·짐대 세트, 차종 연결/입고 기본 장착을 구분한다. 각 기본품 수량은 기존 규칙과 동일하게 1개이다.
품목은 내부 ID로 연결한다. 코드/이름 변경은 다음 열기 또는 최신 자료 읽기에 반영한다. 신규 품목도 마스터에서 직접 읽는다. 사용 중지된 품목은 구성에 경고로 남기고, 교체/제외하기 전 저장을 막는다. 기존 품목 삭제는 사용 중지 방식이며 과거 내역을 지우지 않는다.
세트의 박스/장착·전달 설정은 해당 세트 공통, 구성품 연결은 선택 차종에 적용된다. B2B CUP은 FORZA 전달/그 외 장착을 유지한다. RBZ 입고 기본과 창고에서 별도 전달할 수량을 구분한다.
저장된 규칙은 이후 주문 구성에 사용된다. 진행 중 주문, 출고 Snapshot, 확정 마감, 재고 수량을 자동 재작성하지 않는다.

## 운영 배포와 복구
기준 운영 커밋 bf0007a88bfe3ce9d64d63b80adf6a933033c912에서 이어지는 Git 브랜치에서 구현했다. 운영 코드에 직접 편집하지 않는다.
배포 도구는 운영 서버 신원을 확인해 중지하고 SQLite backup/integrity_check, Data 파일 해시/복사, 환경 파일 해시를 확보한 뒤 검증 커밋으로 ff-only 병합한다. 업무 DB/사진/환경을 개발 환경에서 복사하지 않는다.
재시작 전 모든 DB 테이블 행의 해시가 동일한지, 재시작 후 기존 업무 행과 Data 파일이 보존됐는지 검사한다. 백업 위치/커밋/결과는 운영 폴더 상위 deployment-recovery/parts-rule-builder-*에 기록한다.
복구는 해당 versions.json의 prior와 target을 기준으로 별도 Git 브랜치에서 이번 코드 변경을 revert하고 검사 후 이력을 보존해 배포한다. 이번 변경은 DB 마이그레이션이 없고 기존 서버는 추가 용도 필드를 무시할 수 있다. 배포 후 사용자가 저장한 설정은 업무 변경이므로 DB 전체를 과거 백업으로 되돌리지 않는다. DB 복원은 업무 중지 후 별도 승인과 이후 업무 내역 확인이 필요하다.
GitHub push 없음. 과거 토시 재고 보정/진행 중 주문 수정 작업은 재실행하지 않는다.
